# Design: Terraform-based OVH deployment for PerchPub

**Date:** 2026-06-19
**Branch:** `dev/terraform-ovh-deployment`
**Status:** Approved design — pending implementation plan

## 1. Background & goal

PerchPub currently ships a production-shaped Docker Compose stack (`docker-compose.yml`) fronted by a standalone Traefik (`docker-compose.traefik.yml`) with Let's Encrypt, intended for a single Linux host. Deployment today is manual (see `deployment.md`): provision a host by hand, rsync a Traefik compose file, create a docker network, populate `.env.prod`, `docker compose up -d`. Object storage was external (Hetzner Object Storage / a self-hosted Garage that is commented out in `docker-compose.yml`).

**Goal:** make the existing Compose stack **reproducibly deployable to a single OVH Public Cloud instance via Terraform**, with:

- media + the TF-Lite classification model in **OVH Object Storage (S3 API)** (replacing Hetzner/Garage),
- production secrets **generated by Terraform** and rendered onto the box (never committed),
- DNS records managed in OVH,
- a **Traefik edge that terminates HTTPS (Let's Encrypt) and enforces station mTLS** for `/api/v1/upload/` — closing the known prod-side gap.

Terraform owns the infrastructure *around* the app; the Compose topology (backend, worker, db, redis, step-ca + provisioner-init, frontend, adminer) is preserved as-is. The Hetzner passage in the README is explicitly dropped per the project owner's decision.

## 2. Decisions (with rationale)

| # | Decision | Choice | Rationale |
|---|---|---|---|
| D1 | Terraform scope | **Full single-host stack** — TF provisions instance + block volume + S3 + network + DNS; cloud-init installs Docker and brings up Compose | Mirrors today's well-tested single-host model, made reproducible. Not a cloud-native rewrite. |
| D2 | DNS | perchpub.net stays registered at **Namecheap**; an OVH **DNS zone** is created once and Namecheap's **NS are repointed to OVH**; TF manages records via `ovh_domain_zone_record` against the zone (read via `ovh_domain_zone` data source) | DNS hosting ≠ registration. TF cannot change a foreign registrar's NS, so that step is manual/one-time. |
| D3 | Prod secrets | **TF-generated, rendered on host** via cloud-init `templatefile` | Removes live secrets from git; rotates the leaked ones; secrets live only in (gitignored) state + on the box. |
| D4 | Station mTLS | **Integrate Traefik into the Compose stack** and build the mTLS entrypoint now | Single host → Traefik can mount step-ca's device root CA over the shared volume. Backend is already mTLS-ready (§7). |
| D5 | TF state | **Local, gitignored** | Solo, early-stage. Migratable to an OVH S3 backend later. |
| D6 | Image delivery | **cloud-init clones the repo and builds on the box** (`docker compose … up -d --build`) | No registry to operate; the repo is public on Codeberg. Registry/CI delivery deferred. |
| D7 | OVH region | Default **`GRA`** (Gravelines, FR); a tfvars knob | EU locality. One variable; trivially changed to `DE`/`SBG`/`WAW`. |
| D8 | S3 bucket type | **`standard`** (not `high_performance`) | `high_performance` uses the `EXPRESS_ONEZONE` storage class requiring `put-object` semantics, which can break the Minio client's default upload path. |

## 3. Target architecture

```
Namecheap (registrar)                OVH Public Cloud project
  perchpub.net NS  ──repoint──►  ns##.ovh.net / dns##.ovh.net
                                          │
                                 ┌────────▼─────────┐  ovh_domain_zone_record
                                 │  OVH DNS zone    │  api / dashboard / adminer / @  → A → public IP
                                 └────────┬─────────┘
                                          │
                  ┌───────────────────────▼─────────────────────────────┐
                  │  OpenStack instance (Ext-Net, public IP)             │
                  │  cloud-init: docker + clone repo + render .env.prod  │
                  │  nftables/ufw: allow 22, 80, 443, 8443 only          │
                  │                                                      │
                  │   Traefik ──:443 https (LE)──► frontend / api / adminer
                  │      └──────:8443 mtls (RequireAndVerifyClientCert)──► backend /api/v1/upload/
                  │                 │ passTLSClientCert(pem) → X-Forwarded-Tls-Client-Cert
                  │   backend ─┬─ worker ─ redis ─ db ─ step-ca(+provisioner-init)
                  │            │  named volumes (pgdata, redis, step-ca) ──► /mnt/perchpub-data (block volume)
                  └────────────┼─────────────────────────────────────────┘
                               └── S3 (https, region=gra) ──► OVH Object Storage bucket  (media + TF-Lite model)
```

## 4. Terraform resource inventory

| Provider | Resources |
|---|---|
| `ovh/ovh` (~> 2.x, endpoint `ovh-eu`) | `ovh_cloud_project_storage` (bucket, type `standard`, region `GRA`); `ovh_cloud_project_user` + `ovh_cloud_project_user_s3_credential` + `ovh_cloud_project_user_s3_policy` (scoped key/secret for the bucket); `ovh_domain_zone` (data source) + `ovh_domain_zone_record` (A records: `api`, `dashboard`, `adminer`, and apex/`@` as needed) |
| `terraform-provider-openstack/openstack` | `openstack_compute_keypair_v2`; `openstack_compute_instance_v2` (image Debian 12 / Ubuntu 24.04, flavor default `b3-8`, network `Ext-Net`, `user_data` = cloud-init); `openstack_blockstorage_volume_v3` + `openstack_compute_volume_attach_v2`; `openstack_networking_secgroup_v2` (egress hygiene only — see §5 caveat) |
| `hashicorp/random` | `random_password` ×4 (SECRET_KEY, POSTGRES_PASSWORD, FIRST_SUPERUSER_PASSWORD, STEP_CA_ADMIN_PASSWORD); `random_id`/`random_bytes` → 32-byte hex for ENROLLMENT_HMAC_KEY_HEX |
| backend | **local**, gitignored (`*.tfstate*`) |

Reference: Mastodon's [`terraform-ovh-s3`](https://github.com/mastodon/terraform-ovh-s3) module demonstrates the exact `ovh_cloud_project_storage` + user + credential + policy pattern.

## 5. Networking & firewall (important OVH caveat)

OVH OpenStack **security groups do not reliably enforce ingress on the public network (`Ext-Net`)**. Relying on them to firewall a public-IP instance would be a latent hole. Therefore:

- **Host-level firewall is the enforcement mechanism:** cloud-init configures `nftables` (or `ufw`) to allow inbound **22 (SSH), 80 (HTTP→HTTPS redirect + LE challenge), 443 (HTTPS), 8443 (station mTLS)** only; deny the rest.
- An OpenStack `default` security group is still attached for egress hygiene and intent documentation, but is **not** trusted for ingress filtering.
- SSH ingress should be scoped to an `ssh_allowed_cidr` tfvars var (default `0.0.0.0/0` with a doc warning, recommend narrowing).

## 6. Secrets & `.env.prod` rendering

Terraform generates the app secrets and reads the OVH S3 key/secret from `ovh_cloud_project_user_s3_credential`. The cloud-init `templatefile` renders **`/opt/perchpub/.env.prod`** on the instance at first boot. Rendered values include:

- `ENVIRONMENT=production`, `DOMAIN=perchpub.net`, `FRONTEND_HOST=https://dashboard.perchpub.net`, `BACKEND_CORS_ORIGINS`, `STACK_NAME=perchpub`, `PROJECT_NAME`.
- App secrets from `random_*`: `SECRET_KEY`, `POSTGRES_PASSWORD`, `FIRST_SUPERUSER_PASSWORD`, `STEP_CA_ADMIN_PASSWORD`, `ENROLLMENT_HMAC_KEY_HEX`. `FIRST_SUPERUSER` = the owner email.
- Object storage: `GARAGE_ENDPOINT=s3.gra.io.cloud.ovh.net`, `GARAGE_USE_TLS=True`, `GARAGE_REGION=gra` (see §8), `GARAGE_BUCKET_NAME`, `GARAGE_KEY_ID`/`GARAGE_SECRET` from the S3 credential.
- Classification object names, Huey/Redis host, step-ca paths — carried over from the current `.env.prod`.

**Repo cleanup + security note:** the committed `.env.prod` holds *live* secrets now in git history. They will be **scrubbed to placeholders** in the repo (the rendered file supersedes the committed one for prod), and must be treated as **compromised** — the TF-generated values replace them, so a fresh deploy is clean. Git-history purge is out of scope (optional follow-up). No `.gitignore` rule is needed for the rendered `.env.prod` — it exists only on the box, not in the repo; the repo's committed `.env.prod` simply becomes a non-secret template aligned with `.env.example`.

## 7. Edge: Traefik + HTTPS + station mTLS

A new **`docker-compose.prod.yml`** overlay adds a `traefik` service to the perchpub stack (superseding the standalone `docker-compose.traefik.yml` model, so Traefik can mount step-ca's device root CA over the shared `step-ca` volume).

- **`http` entrypoint `:80`** — ACME HTTP/TLS challenge + redirect to HTTPS.
- **`https` entrypoint `:443`** — LE cert resolver (`le`); reuses the existing router/middleware **labels already declared on backend/frontend/adminer** in `docker-compose.yml` (rate-limit middlewares WI-14, https-redirect, host routers). Traefik's `traefik-public` network requirement is satisfied by the in-stack Traefik joining the same network.
- **`mtls` entrypoint `:8443`** — a `tls.options` block (`clientAuth.clientAuthType = RequireAndVerifyClientCert`, `clientAuth.caFiles = [<device root_ca.crt>]`) and a `passTLSClientCert` middleware with `pem: true` that sets `X-Forwarded-Tls-Client-Cert`. A router matches `Host(\`api.perchpub.net\`) && PathPrefix(\`/api/v1/upload/\`)` → backend service + that middleware. Stations POST to `https://api.perchpub.net:8443/api/v1/upload/` with their client certificate.
- **Device root CA** is read from the `step-ca` named volume (`certs/root_ca.crt`), mounted read-only into Traefik. step-ca + `step-ca-provisioner-init` already populate it.

**No backend changes for mTLS.** Verified: `backend/app/core/config.py` defines `MTLS_CLIENT_CERT_HEADER = "X-Forwarded-Tls-Client-Cert"`; `backend/app/api/deps.py` reads that header, base64-decodes the leaf, runs `verify_directly_issued_by(device_ca)` (CA from `settings.DEVICE_CLIENT_CA_CERT_PATH`), computes the SPKI SHA-256, and matches `Station.spki_sha256`. A code comment states "prod-side mTLS wiring is the deferred follow-up to mTLS-05" — i.e., only the Traefik edge was missing. The edge's `passTLSClientCert.pem=true` output and the backend's decoder must agree on encoding; verify the exact transform at plan/implementation time against `deps.py`.

## 8. Required app change: configurable S3 region

The Minio client is constructed with **`region="garage"` hardcoded** in `backend/app/api/routes/uploads.py:25` and `backend/app/tasks.py:48`, and config has no region field. OVH S3 validates the SigV4 credential-scope region; a `garage` region against OVH yields `SignatureDoesNotMatch`. Change:

1. Add `GARAGE_REGION: str = "garage"` to `backend/app/core/config.py` (default preserves Garage/dev + Minio/test behavior).
2. Replace the two hardcoded `region="garage"` with `region=settings.GARAGE_REGION`.
3. Set `GARAGE_REGION=gra` in the rendered prod `.env.prod` (must match the bucket's region; OVH API region casing is uppercase `GRA`, S3 signature region is lowercase `gra`).
4. Add `GARAGE_REGION` to `.env.example` / `.env.prod` template / `.env.dev` (value `garage`) and `.env.test` (value `garage`, Minio is lenient).

This is the only application code change required by the migration.

## 9. Persistent storage mapping

Attach a block volume, partition/format (ext4) and mount at **`/mnt/perchpub-data`** via cloud-init (giving the currently-orphaned `PERCHPUB_VOLUME` var a real purpose). The Compose named volumes `pgdata`, `redis`, `step-ca` are bound under that mount (compose `volumes` with `driver_opts: {type: none, o: bind, device: /mnt/perchpub-data/<name>}`, created in the prod overlay) so **Postgres data and the step-ca root survive instance rebuild/replacement**. Media and the TF-Lite model live in **S3**, not on the block volume.

## 10. File layout (new `deploy/terraform/`)

```
deploy/terraform/
  providers.tf            # ovh + openstack + random, versions pinned
  variables.tf            # project_id, region, flavor, image, domain, owner_email,
                          # ssh_pubkey, ssh_allowed_cidr, repo_url, volume_size_gb
  secrets.tf              # random_password / random_bytes
  storage.tf              # S3 bucket + user + credential + policy
  compute.tf             # keypair, volume, instance, attach, secgroup
  dns.tf                 # ovh_domain_zone data source + A records
  cloud-init.yaml.tftpl   # docker install, volume format+mount, repo clone,
                          # .env.prod render, compose up -d --build
  outputs.tf              # public IP, S3 endpoint/bucket, NS-repoint reminder
  terraform.tfvars.example
  README.md               # bootstrap + apply runbook + smoke test
  .gitignore              # *.tfstate*, .terraform/, *.tfvars (except .example)
```

## 11. One-time manual bootstrap (in the TF README)

1. Create OVH API credentials (application key/secret/consumer key) for the `ovh` provider.
2. Have a Public Cloud project; copy its `service_name` (project ID) → tfvars.
3. Generate OpenStack `clouds.yaml`/openrc for the `openstack` provider.
4. Create the OVH **DNS zone** for `perchpub.net` (Control Panel/API) and **repoint Namecheap NS** to OVH's nameservers; wait for propagation.
5. Fill `terraform.tfvars`; `terraform init && terraform apply`.
6. Post-apply smoke test (§13).

## 12. Repo changes summary

- **New** `deploy/terraform/` (as above).
- **New** `docker-compose.prod.yml` (Traefik service with http/https/mtls entrypoints + device-CA mount; volume binds to `/mnt/perchpub-data`). Production brings the stack up with `-f docker-compose.yml -f docker-compose.prod.yml`.
- **Modify** `backend/app/core/config.py`, `backend/app/api/routes/uploads.py`, `backend/app/tasks.py` for `GARAGE_REGION` (§8).
- **Modify** `.env.example`, `.env.prod`, `.env.dev`, `.env.test` to add `GARAGE_REGION`; scrub `.env.prod` secrets to placeholders.
- **Docs:** rewrite the Hetzner / standalone-Traefik / manual-host sections of `README.md` and `deployment.md` to reference the Terraform runbook; keep step-ca and secret-generation guidance. Update `CLAUDE.md` deployment notes.
- Decide the fate of `docker-compose.traefik.yml` (remove or mark legacy) once the in-stack Traefik lands.

## 13. Testing & verification

- **Static:** `terraform fmt -check`, `terraform validate`, `terraform plan` (no apply without creds); optional `tflint`. `shellcheck` the rendered cloud-init script body.
- **App change:** existing backend test suite still passes with `GARAGE_REGION` defaulted to `garage` (no behavior change for dev/test).
- **Post-apply smoke test (manual runbook):**
  1. `curl https://api.perchpub.net/docs` and `https://dashboard.perchpub.net` resolve with valid LE certs.
  2. First-superuser login works (seeded by `prestart`).
  3. Enroll a station; perform an mTLS upload to `:8443/api/v1/upload/`; confirm a classification task runs (worker) and the object lands in the OVH bucket.
  4. Reboot/replace the instance; confirm Postgres + step-ca state persist from the block volume.
- Full `apply` requires real OVH credentials + billing → it is a documented manual step, **not** CI-gated.

## 14. Risks / plan-time verifications

- **OVH S3 endpoint hostname & region casing** per chosen region (`s3.gra.io.cloud.ovh.net`, API `GRA`, signature `gra`) — confirm against current OVH docs at implementation.
- **`passTLSClientCert.pem` encoding** vs. the backend decoder in `deps.py` — confirm the exact base64/URL-encoding transform end-to-end.
- **`ovh_cloud_project_storage` arguments** (region/name/versioning/encryption, S3 policy shape) — pin against the current provider schema.
- **OpenStack provider auth on OVH** — `clouds.yaml` vs. app-credentials; flavor/image names current for the region.
- **`traefik-public` external network** — when Traefik is in-stack, decide whether to keep the external network or collapse to the stack's `default` network (the existing labels reference `traefik-public`).
- **Frontend build arg** `VITE_API_URL=https://api.${DOMAIN}` is set at image build time; building on the box must have `DOMAIN` available to compose at build (it is, via `--env-file`).

## 15. Out of scope (YAGNI)

Staging environment; managed Kubernetes / managed Postgres; remote TF state backend; CI/CD auto-deploy; multi-region/HA; git-history secret purge; registry-based image delivery. All deferrable; none block this work.
